# Legacy controller adoption

## Implementation status

The optional [legacy migration utility](../tools/legacyimport/README.md) implements bounded read-only inspection, selected current job/checkpoint conversion, selected message conversion and selected completed review preparation from an explicit sealed SQLite export. Native administrator preview/apply and the bound CLI preserve private source provenance and subsequent native edits or message handling. [Operational review adoption](review-round-controls.md#prepared-operational-adoption) carries remaining limits and original taper state separately from native captured credit. The offline source-helper adapter accepts an explicitly supplied canonical effective-history frame. A separate optional source-owner acquisition command binds sealed source state and captures, audits canonical obligations and confines Git proof writes to an owned scratch clone; neither command establishes a durable source-writer fence. See the [source-owner procedure](../tools/legacyimport/README.md#acquire-a-source-owner-history-frame). Focused SQLite/HTTP/client and backup proof is recorded at the owners; the combined packaged conversion/application results and their source checkpoints are recorded in the [executed adoption proof](#executed-message-and-operational-adoption-proof). Notes, updates, checklists and full prior job histories remain outside the selected path. Prepared review and project-map imports retain their separate guarded application paths. Native backup restore/schema upgrade does not convert a legacy controller. A selected paused-source hosted load has qualified coordination and project content, completed display history, a complete source-owner carried frame, native controls/holds and distinct authenticated worker bindings. Full-data recovery and worker resume remain separate cutover boundaries.

## Selected job snapshot import

The version-one prepared batch contains `version`, positive `repository_id`, explicit `expected_revision`, a stable `source` namespace, sealed `source_sha256` and one to twenty-five `jobs`. Each job contains an opaque unique `source_key`, original `source_revision`, title/brief/status, an explicitly mapped native `worker_id`, original creation/update timestamps and selected checkpoints. There are at most one hundred checkpoints per batch, and the complete normalized apply wrapper fits 256 KiB. Ordinary native text/byte/time constraints apply; a source document that needs summarizing or editing is refused rather than silently rewritten.

This format imports an explicitly selected current job snapshot as native revision 1. Original source revision remains in provenance; this is not a reconstruction of every prior native revision. Selected checkpoints retain their source keys, original text, timestamp and input order. Their native `job_revision` is 1, the selected imported snapshot. A source without recorded checkpoint authors uses the reserved `imported-history` attribution with no actor worker, explicitly meaning unavailable original attribution. It does not guess authors from current assignment. Original named source pointer JSON is retained as inert evidence text when it fits native limits.

`GET /api/v1/projects/{project_id}/coordination/imports` returns the compact current import revision, initially 0. Administrator `POST .../coordination/imports/preview` accepts the prepared batch and returns selected/new/unchanged counts with payload and preview fingerprints. `POST .../coordination/imports/apply` accepts `{preview_sha256,batch}` and an explicit idempotency key. All require current administrator authority and explicit importing-worker context. Preview binds content, instance, project, principal and worker. New apply rechecks repository identity, import revision, worker references and source mappings in the ordinary two-second transaction. It calls no provider.

Stable source identities produce project-bound native job/checkpoint IDs. Source mappings, normalized originals, sealed source digest, original source revision and import actor/time remain private durable provenance. Existing mappings accept identical source items without overwriting later native edits; conflicting items refuse. Same-key exact replay returns the original compact receipt before checking a newer import revision, with current authorization still required. A new-key unchanged import records a receipt without advancing import revision, duplicating records or emitting another event. A changed import commits native records, provenance, revision, receipt and one compact `coordination.imported` metadata event atomically. Active job, inbox and conversation views refresh; historical message-delivery events are never replayed.

The bound administrator commands are:

```sh
fc import state
fc import preview --file /private/import/jobs.json
fc import apply --file /private/import/jobs.json --preview SHA256 --key selected-import-key
```

The CLI checks strict bounded private input before credentials or service access and uses the ordinary five-second client budget. Keep the exact file, fingerprint, key and binding for uncertain-output recovery. These setup operations do not add worker MCP mutation tools or make imported source history native review coverage.

## Selected message import

The existing version-one prepared coordination batch accepts up to one hundred selected messages, optionally alongside twenty-five jobs and one hundred checkpoints, within the same 256 KiB apply budget. Message-only batches contain `jobs: []`. Each message retains its stable source key, original body and creation/handling timestamps, explicit mapped sender/recipient and optional reply source key. Native recipient flags reflect the original known handling state; original handling times remain in private provenance. No author, receipt or acknowledgement is inferred.

A reply parent must be in the selected batch or have an existing retained mapping in the same source namespace. The service resolves bounded selected graphs independently of input order and refuses missing, cyclic, foreign or mismatched participant relationships. Stable project/source identities create native messages and conversations. Preview performs no writes; apply commits jobs/messages, original provenance, revision, receipt and one compact import metadata event together. It emits no historical send, delivery or handling events. Imported pending messages remain visible in deliberate inbox/context reads.

Exact replay preserves the original receipt. A new unchanged batch does not duplicate messages or undo subsequent native acknowledgement. Snapshot validation checks immutable originals and the monotone recipient-state path; inactive restore preserves both original source facts and later native handling. The optional `prepare-messages` converter requires explicit selected IDs, worker mappings and an archive policy for source job/PR annotations unsupported by native message associations. It neither chooses a backlog nor truncates text. Unmapped authors and dependencies refuse; an unknown original author requires its own explicit destination worker mapping.

## Selected completed review history

The optional source-specific `prepare_source_reviews.py` prepares explicitly selected completed, finalized review runs and their known findings from a sealed export. It produces a bounded [additive review transfer](review-import.md#additive-mixed-producer-transfer), independently of effective round-control preparation. A canonical policy frame is not a display-history export: it does not contain finding text, individual decisions or fix proof.

The operator supplies the trusted source package, sealed snapshot, explicit run IDs and offline PR metadata. Loading that package executes trusted source code; the converter never discovers an installation, contacts GitHub or uses credentials. The declared repository identity and PR metadata are operator-supplied facts bound into private provenance, rather than newly verified provider observations. Native preview checks the destination identity and retained metadata before application.

Selected runs retain their source identities, channel, reviewer, scope, genuine completion times and known finding text. Where the source retains original finalized counts, those remain distinct from later effective count corrections. Otherwise the converter preserves canonical exported counts and records that original finalization counts are unavailable; it does not reconstruct them from decision times. Effective source decisions and supported fixes retain their original actors, reasons, times and proof; private provenance preserves correction details. Where later corrections differ from original counts, a coverage note makes that distinction visible without rewriting either fact. Missing or unrepresentable selected facts refuse preparation rather than being shortened or invented. A run declares complete finding coverage only when the retained findings match its exported count. Every transferred PR declares partial coverage.

Attempts, raw captures and receiving-route ledger history stay in the private source archive. They are not required to display the selected runs and findings, and the omissions remain explicit. This import creates neither native captured review credit nor current control settings, and does not resolve old obligations. Effective controls still use their separate settled source-owner acquisition and adoption path. Imported text remains inert data.

See the [utility guide](../tools/legacyimport/README.md#prepare-selected-completed-review-history) for inputs, bounds and exact retry behavior. The destination's ordinary administrator transfer preview/apply remains the authority for admissibility and conflict handling.

## Retention and conversion

The [unfinished-obligation contract](adoption-obligations.md) defines the carry path for projects whose current findings or routes remain open. Native enforced holds, explicit resolution, policy linkage and minimum-only policy are implemented. Complete carried-frame collection remains a source-owner responsibility outside the packaged tooling; the live acquisition command must continue refusing sources that lack clearance. The offline preparer accepts the strict carried format only with matching retained native previews, as defined at that owner. A successful coordination or display-history import does not establish full review cutover readiness.

Import useful selected project state rather than requiring every historical detail. The operator selects the source export, destination project and historical scope. Preview reports selected, excluded and unsupported record classes explicitly. Never silently truncate a brief, invent a missing author/time, convert an instruction note into another kind or mark old messages handled to simplify migration. Keep original source bytes privately with their digest when a selected fact cannot be represented faithfully.

The source-specific converter lives under `tools/`; the daemon accepts a versioned native prepared format through reusable administrator-only facilities. It must not depend on legacy table names, paths, Python modules or installed project conventions. Ordinary job creation and message sending are not historical import APIs: they allocate new identities/times and have current operational effects.

Selected coordination records preserve stable source keys, original timestamps, worker attribution, job state, brief/checkpoint/update/checklist relationships and message reply/handling facts where representable. Native identities can differ, but durable explicit source mappings must make retries and references unambiguous. Names are display data, not implicit identity matching. Source authors that are not known workers need an explicit mapping or an unsupported-record result. Unselected parents/dependencies must be included explicitly or cause a visible conflict; do not quietly fabricate them.

Before adopting operational controls, the source owner must verify that accepted findings and incoming/outgoing routed obligations are resolved or completely retained as enforced native holds, including obligations outside the selected display history. Quiescence alone does not establish that proof. The live acquisition command requires clearance. The offline control preparer also accepts a complete carried frame bound to retained native holds; pending known findings require exact row-to-obligation bindings, while unknown evidence still refuses. An explicitly deferred channel produces no numeric control or closure-only substitute. Display-history imports remain inspectable data and never substitute for the independent native hold ledger. Unfinalized source results with deferred allowance or taper effects require a faithful accounting boundary before dispatch can resume. Exhausted limits, taper and closure must not silently discard unfinished work. This prerequisite does not require rerunning finished historical reviews and does not grant native comparison coverage.

Historical text is inert imported data. Import does not send messages again, acknowledge an inbox, resume a worker, run a provider, publish private information or turn a historical review into native captured evidence. Current primary-job, pause and appearance settings are deliberate configuration choices, separate from retained historical facts. Imported operational review settings follow the selected round-control contract; retrospective allocation/credit bookkeeping can remain in the private archive.

## Guarded application

Preview is read-only and binds normalized content, source provenance, destination instance/project and current administrator/worker identity. Apply uses an explicit idempotency key and rechecks current authorization, conflicts and expected destination state within the write transaction. Same-key exact replay returns the retained result; changed content or conflicting mappings refuse without partial effects. Imported source keys cannot overwrite newer ordinary edits. Bounded batches and explicit continuation make large imports resumable without treating a partial batch as complete coverage.

Current/history rows, source mappings, import provenance and receipt commit together. Historical source times remain separate from application time. Emit only the compact import notification needed to refresh affected native views, rather than replaying historical message events to attached agents. Imported pending coordination must remain deliberately discoverable through the supported native context/inbox reads. Public visibility stays unchanged.

## Required proof before adoption

Use synthetic legacy exports to prove conversion, exact retry/restart, changed-input refusal, dependency/conflict handling, rollback, source conservation, original time/identity attribution, byte-limit failures, project isolation and no provider/send/publication side effects. Exercise the actual optional utility and packaged service/CLI, then inspect populated browser views. Rehearse an explicitly authorized real-project load separately before cutover; inspection success, synthetic proof and review approval do not authorize that load or operational replacement.
