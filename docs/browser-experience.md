Worker lane cards contain their assigned open jobs, including primary focus and other concurrent jobs. An Unassigned lane contains open jobs without an owner. Cards show concise current activity, job state, blockers and the next useful step with links into full context. Worker pause is an explicit coordination fact, never inferred online presence or a job status. Worker lanes with active work come first, then lanes with blocked or parked work, then workers without loaded open jobs. Within each lane, the explicitly selected primary job comes first, followed by active, blocked and parked work. A parked primary job does not move a lane with other active work behind inactive lanes. Red worker headers provide inbox and filtered job-history links; the lane contains distinct job cards, with status and primary-focus pills beside their titles when space allows. Unassigned work remains a separate lane. Completed jobs remain available in Jobs rather than crowding the default board; lane order does not claim agent presence.

The default view needs no worker selection or filter configuration. Inbox actor selection never filters Delivery. Jobs remains a separate management view with status/worker filters, completed history and a future home for deliberate creation/editing; browser job mutations are not implied by this redesign. Worker details and histories remain secondary links from lanes.

Current Review front labels use the independent [stored channel-front assessment](review-fronts.md), bound to the loaded workspace and PR identity. Queued labels require an established earlier front; Review closed uses current configured round controls. Unknown or stale assessment does not borrow meaning from the merge-head rail. Operation changes invalidate only the active current progress/front views, without reloading pinned review bodies.

The review/merge queue sits below the lanes, with distinct Hosted and CLI groups, actual findings, taper/limits and CI facts where available. The default queue shows merged PRs for 48 hours and keeps at least the latest two known merges visible. Unknown merge times stay visible. Queue history shows every retained merged PR in reverse configured order. Hiding an older merged row never removes its stored queue entry, review rounds or findings; only explicit defunct/superseded work is retired. Delivery embeds the same full review queue renderer as the focused Reviews route, including per-channel run counts, round history and explicit continuation. The hero links down to that queue. Project-configured review-group headings preserve the queue order rather than rearranging work into label buckets. A coloured rail and signed positions show distance from an established first open head; a partial or ambiguous slice does not invent a global rank. Merged rows and pills use the project’s purple merged palette. The compact guide explains request states and the three-number counts without claiming unavailable source facts. Completed attempt prose and redundant retained-history labels do not crowd the queue. Missing PR details identify the actual unknown fields behind an expandable disclosure. Detailed PR/run pages supplement the overview without making routine monitoring require several screens. Ordinary timestamps use relative ages, with precise dates available on hover or in source details. A single primary label occupies the lifecycle position: Merged or Closed for those states, otherwise the verified review status. Do not repeat Open or place a second review-status label beside the title. Global snapshot provenance stays inside Source details because a mixed-age queue has no single review freshness time.

The hero is one joined, two-tone surface, with project identity vertically centered on its left. Its right side presents the merge-train head PR with its title, meaningful stored review/CI state and a link to inspect it. Select the head from actual stored queue ordering and eligibility; an incomplete bounded slice cannot establish that no head exists. Keep Hosted and CLI progress distinct and retain freshness/unknown states. This card must not fetch GitHub or start a review. Remove decorative workflow filler. Refresh rereads stored service data and never starts provider work. Remove duplicate hero utilities and visible internal project IDs. With no head, the hero contracts rather than leaving an empty panel.

Reads stay bounded and project-scoped. Reuse stored summaries and live invalidation; never expand every job brief, checkpoint, note archive or provider capture to paint the board. Expose continuation or partial coverage honestly at larger sizes, without presenting a partial page as the full project. Desktop and narrow layouts preserve readable lanes, a clear queue and stable loading geometry. ## Delivery read contract

`GET /api/v1/projects/{project_id}/delivery` requires project read access and returns `workers` and `jobs`, each an independently bounded `items`/`cursor`/`has_more` collection from one local read transaction. `worker_limit` defaults to 20 and `job_limit` to 50, each capped at 100; `worker_cursor` and `job_cursor` bind the project, principal and ordering. Unknown, repeated or malformed selectors fail validation. Worker order is stable ID order; open jobs use active, blocked, parked then ID. Completed jobs remain outside this overview.

Workers include their identity/name, selected primary job, explicit pause state and a pause-reason preview. Jobs include compact title/state/revision/assignment and worker name, a bounded standing-brief preview, the job's last recorded edit time (any job field), an optional latest narrative-update preview, current checklist done/total counts, and their optional latest checkpoint with done/next/blocker previews. Narrative updates and checkpoints retain their sequence, captured job revision and recorded time; the current checklist retains its checklist revision, captured job revision and recorded time. Missing update/checklist records remain absent; a known empty checklist remains distinguishable. Each prose preview is at most 240 UTF-8 bytes with an explicit truncation flag; full details remain deliberate reads. No full briefs, checklist item text, evidence arrays, history archives, provider captures or implicit provider refresh are included. Captured job revisions stay visible so older progress cannot masquerade as an update to a newer job brief. These facts share the same bounded local transaction and use indexed latest-row/current-row lookups rather than browser request fanout.

The browser groups this bounded job slice into lanes. An ordinary complete board has no pagination controls. When a project exceeds the initial bounds, an explicit Load more work action appends one bounded continuation instead of replacing existing lanes or jobs. A refreshed first read discards the old appended tail; late responses cannot restore it. An assigned job whose worker lies outside the worker slice still carries its worker name and never becomes Unassigned. A partial job page does not establish that any lane is complete. Continuation remains explicit without automatically walking an entire fleet. The full queue loads at most one initial bounded round page per displayed PR, shared with the hero through the query cache; further rounds require an explicit action. A partial channel count says that only shown runs are counted. It does not substitute a mixed total for Hosted/CLI counts. Job creation/edit, narrative-update append, checklist replacement, checkpoint append, worker creation/pause/focus and broad resynchronization invalidate this stored summary; unrelated message arrivals do not require rereading every job.

Job cards show useful standing context and progress directly, with compact checklist counts and contextual relative ages. The job's last edit, narrative updates and checkpoints retain separate recorded times; the view does not invent one combined activity time or claim that a wall-clock timestamp establishes sequence order. Imported times and clock rollback remain visible through the ordinary date-unknown/future-date behavior. Full histories remain secondary links.

## Authored Markdown

Full job briefs, checklist text, checkpoints, updates, conversation messages, contextual note bodies/reasons and review finding/decision/proof narratives use the same safe Markdown renderer as editorial content. Ordinary prose is valid Markdown; writing does not require a rigid template, special headings or a formatting-lint round trip. Titles, status enums, identifiers, evidence references and worker pause previews stay literal. The bounded Delivery brief, update and checkpoint prose previews reuse the same safe renderer with compact typography and headings below the job title. Truncated Markdown may leave an incomplete construct literal; the explicit truncation marker remains visible and does not cause a full-body read. Render headings within the page hierarchy, lists, emphasis, quotes, code and safe links consistently. Raw HTML stays escaped, unsafe links remain inert and remote images do not load automatically. Rendering stored text never executes instructions or changes authorization, message acknowledgment, job state or review policy. No extra API/history reads are needed to format an already selected body.

## Editorial Project page

Project explains what the project is, its direction and progress as a coherent website. It replaces the record catalogue as the primary map presentation. Content has flexible editorial depth: a substantial Markdown section, a short update, an initiative with subsections, a milestone, or contextual deferred direction are all legitimate. Progress, dates, status labels, phases and links are optional aids, not a mandatory checklist shape.

Use readable section hierarchy, generous but purposeful typography/spacing and appropriate full-width narrative, cards or columns. Render the actual content in the page rather than requiring a click through each summary. Do not present every entry as the same boxed database row or surround prose with empty metadata placeholders. Preserve project-configurable appearance, the selected default branding and platform attribution.

Markdown is an appropriate authoring format; storage and APIs must preserve its expressive content and deliberate order. Render supported prose, headings, emphasis, lists, quotes, code and safe links as content. Raw HTML, scripts, arbitrary CSS and automatic external embeds do not acquire authority from Markdown. Existing plain editorial records and historical revisions remain readable; optional structured progress remains available. The domain contract at [project map](project-map.md) owns exact persisted shape, bounds, history and import behavior.

A return point can remain editorial context when it explains project direction. Actionable reminders belong on jobs or contextual notes, with links where helpful. Do not automatically reclassify, import, deliver or resolve those records.

## PR history inspection

The PR detail page groups retained Hosted and CLI rounds with their own source-ordered rows, summarized found/accepted/routed counts, outcome uncertainty and relative age. Other retained review types remain identifiable. Expanding a row fetches only that selected run and displays its findings, decisions and fix proof inline using safe Markdown. Collapsing cancels the owned request and removes its detail query from the private cache. Snapshot, project, connection and run identity scope each detail read; loss of access hides retained detail. Explicit bounded continuation loads more round summaries without fetching every finding. Individual pinned run pages remain secondary deep links.
