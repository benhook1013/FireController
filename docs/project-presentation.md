## Stored presentation

The default masthead uses bundled Inter semibold, with a proportional flame and compact gap. Its CSS family is isolated so loading the header font does not change body typography. Font selection is a packaged default; presentation input does not accept fonts or uploaded assets.

One project owns one independently revisioned presentation record. The configuration contains `name`, `brand_name`, `tagline`, `headings`, `theme` and optional `review_groups`. `name` is the canonical project display name: a successful change updates `projects.name` in the same transaction, without changing project ID, repository identity, workers or profiles. The other fields affect the browser only; endpoint names, statuses, tool schemas and JSON fields are never renamed by presentation settings.

Name is required, trimmed nonempty text up to 200 bytes, with no Unicode control characters. Presentation replacement trims surrounding whitespace before validation. New project creation applies the same length and control-character bounds before repository verification, but refuses surrounding whitespace instead of trimming it. A retained project with an older invalid name is not renamed by a read: its implicit revision-0 snapshot retains that name. CLI, MCP and browser clients accept a nonempty UTF-8 retained name up to 200 bytes, without trimming or repairing it. Configured names at revision 1 and later retain the stricter validation. An administrator can explicitly replace presentation at expected revision 0 with a valid name. That replacement can repair the name without first requiring the old implicit name to validate. Brand name and tagline default to the existing `FireController` and `Project workspace`, are trimmed nonempty text up to 120 bytes, and reject controls. Headings is an optional map with exactly these supported keys: `jobs`, `workers`, `inbox`, `reviews`, `map`, `notes`, `hero_eyebrow`, `hero_title`, `hero_description`. Values are trimmed nonempty single-line text up to 240 bytes. Missing keys retain the existing interface wording. Other operational labels remain service vocabulary, not a translation framework. Unknown fields/keys, malformed Unicode and scalar null fail validation; omitted maps normalize to empty objects.

Theme is an optional map of supported semantic tokens to six-digit `#RRGGBB` colors, normalized lowercase. No CSS expressions, selectors, script, HTML, URLs, fonts or asset uploads are accepted. The supported tokens and reference colors are:

The shared pure `internal/presentationmodel` package owns configuration normalization and validation without SQL or HTTP dependencies. Its embedded `defaults.json` contains the `theme` reference palette and `headings` defaults; browser validation imports that same data. Go clients do not import SQL/HTTP implementation packages. CSS uses bounded token variables with its exact existing selector colors as fallbacks. With no overrides, preserve the existing refined red dashboard in color, typography and layout, with the masthead font and spacing defined above as the intentional default update; any nonempty theme applies the resolved semantic palette (reference colors plus explicit overrides), so foregrounds match the reference values used by validation. Clearing the theme restores each exact stylesheet fallback. Shadows and noninformational transparency need not become settings. All informative foreground, background, border and focus colors must be assigned to an appropriate supported role rather than leaving project-specific red or dark text behind in a custom theme. Default flame/favicon and platform attribution remain; custom assets are outside this contract.

Validate each pair when either of its tokens appears in the override map, even if the supplied color equals its reference value. Text and muted tokens pair with their own canvas, surface, header or hero background. Accent text pairs with accent background; accent background also pairs with canvas and surface backgrounds because it serves links. Soft accent backgrounds pair with surface text, surface muted text and accent links. Each status text pairs with its corresponding status background. These pairs require contrast at least 4.5. Focus pairs with canvas, surface, header, hero, accent, soft accent and each status background, requiring 3 whenever focus or that background is overridden. Missing members use reference colors; calculate contrast through sRGB relative luminance. Entirely unmodified default pairs retain the established appearance; this is not an assertion that every existing small label already meets accessibility criteria. Reject an invalid override rather than quietly changing its color. Actual desktop/narrow browser proof of configured themes complements these semantic checks; this is not a claim of complete accessibility compliance.

The canonical JSON configuration is at most 16 KiB, within the existing API request ceiling. A replacement supplies `expected_revision` and `presentation`; it replaces the complete configuration, so omitted optional overrides clear to defaults. Fast local mutations return compact receipts, with explicit keys and no operation-polling cycle. Current authorization is checked on exact replay. A no-op preserves revision/history/events while recording the receipt for its new key.

## API and history

Paths are under `/api/v1/projects/{project_id}`. Reads require project read access. Replacement requires existing administrator authority and an explicit worker binding; receiving a message never grants that authority. Browser appearance writes require an administrator session, its login-time permission ceiling and the existing worker binding; messaging follows the session's separate write permission.

| Method and path | Contract |
| --- | --- |
| `GET /presentation` | One authorized read transaction returns `{presentation,event_cursor}`: current configuration/revision plus atomic project-metadata watermark. |
| `PUT /presentation` | Explicit key, nonnegative expected revision and complete replacement configuration; receipt `{project_id,revision,outcome}`. |
| `GET /presentation/history` | Compact revision/actor/time summaries, newest first, default 25/max 100, explicit cursor. |
| `GET /presentation/history/{revision}` | One complete captured configuration with its actor/time. |
| `GET /project-events/stream` | Persistent authorized metadata SSE from the explicit cursor, limit 1–100/default 25. |

The current presentation object contains `project_id`, `revision`, the configuration fields and `updated_at`; empty `review_groups` is omitted. A project with no presentation record returns revision 0 and empty updated_at with its current project name and default configuration; reading does not allocate rows. There is no retained revision 0. Current/history data is private. History freezes configuration and name, not the rendered pixels of future browser releases. The history `actor_id` identifies the authenticated principal; it does not retain a separate worker ID. The explicit worker binding distinguishes keyed mutations in the receipt fingerprint.

Configuration, immutable history, canonical project-name update, compact event and receipt commit together. Events contain only identifiers/revisions. Histories are contiguous, and current settings agree with their last snapshot and canonical project name. Inspection/restore preserve those bindings; startup installs the optional domain before serving. No provider or filesystem tracker is consulted by a presentation command.

## Review group headings

Optional `review_groups` is an ordered array of `{title,pull_numbers}` for private queue presentation. Each title is trimmed nonempty single-line text up to 160 UTF-8 bytes. Up to 40 groups and 1000 total positive PR numbers through 2147483647 are allowed within the existing 16 KiB configuration budget; titles and PR memberships are unique. Each group has at least one PR. Unknown extra fields, malformed values, duplicates and explicit null are rejected. Omission or an empty array clears the labels on replacement. A label may name a future PR that is not in the stored queue yet.

The browser renders headings over consecutive matching rows in the actual stored order, repeating a heading when needed rather than regrouping/reordering the train. These labels do not change queue membership, selection, review requirements, channel closure or provider requests. They share the existing project presentation revision, history, authorization, replay and metadata event. No per-PR metadata fetch is added. Public manifests reject private review groups; public review enrollment remains separately explicit.

Merged review styling has independently configurable `merged_background`/`merged_text` and `merged_rail`/`merged_rail_text` pairs. The defaults retain the established purple merged treatment. Both text pairs require 4.5:1 contrast. Explicitly configured `merged_background` and `merged_rail` colors also require focus contrast of at least 3:1. Adding these roles does not invalidate retained themes that omitted them.

## Separate project-metadata stream

The private project feed has an explicit allowlist of committed changes:

- Appearance and map: `project.presentation_changed`, `map.entry_created`, `map.entry_updated`, `job.workstream_changed`.
- Job progress: `job.created`, `job.updated`, `job.checkpointed`, `job.update_appended`, `job.checklist_replaced`.
- Workers and notes: `workers.created`, `worker.pause_changed`, `worker.primary_job_changed`, `note.created`, `note.updated`.
- Visible review state: `review.observed`, `reviews.policy_configured`, `review.evidence.adjudicated`, `review.evidence.finalized`, `review.evidence.fix_recorded`, `review.evidence.routed`, `review.route.routed`, `review.route.superseded`, `review.route.adjudicated`, `review.route.fix_recorded`.

Internal preflight, allowance queries, source refresh/publication worker chatter, messages and unknown future event kinds are excluded. Evidence changes remain relevant even when an administrator replaced the workspace and retained native evidence is absent from its current projection. Both caller mutations and background worker writes publish notifications only after successful commit; rollback and failed commit produce no hints. There is no new polling loop.

The feed is authenticated project data, not a public projection. The [public website](public-site.md) has a separate publication boundary. The project feed exposes the existing durable sequence through an opaque cursor, not bodies, names, settings, messages or provider captures. A page is `{items,event_cursor,has_more}`; each item contains `event_type`, `resource_id`, `revision` and its own `event_cursor`. Ordering is ascending durable sequence; delivery is at least once. There is no acknowledgment mutation.

Cursors bind instance, principal, project and the project-metadata feed namespace. They are intentionally independent of the browser's selected worker because this is project-wide read authority. Message cursors remain independently bound to their incoming-message scope and cannot be exchanged. Registration precedes the first durable read; a snapshot watermark and later replay cannot miss a committed change. Advance across irrelevant sequence gaps without inventing an item. Reject ahead/malformed/cross-scope cursors and use the existing seven-day replay-eligibility boundary; expired replay requires a fresh presentation snapshot before resubscribing.

Use the same bounded, coalescing in-process wakeup mechanism and shared subscription limits (1024/process, 16/principal) as the existing feed, with an explicit feed namespace. Project metadata wakes project metadata subscribers only; it does not wake every agent inbox. Credential revocation wakes affected subscriptions promptly. No idle JSON or database polling, provider work, writer lock, stored cursor or destructive retention task is introduced.

SSE frames use event name `project-events`; heartbeats, safe errors, two-second write/flush bounds, frame limits, current authorization checks and daemon/request cancellation follow the established [message stream](message-events.md) transport guarantees. Reuse lifecycle primitives rather than maintaining a second divergent reconnect/timeout implementation. The incoming-message API, wire types and call-owned agent waits do not change.

## Browser application and isolation

Obtain the authorized presentation/watermark before starting project content queries. Subscribe from that watermark, invalidate canceled pre-event reads, refetch active affected queries and advance the processed cursor only after successful handling. Map events invalidate relevant map/reference queries; presentation events reread current settings/name. Job, worker and note events invalidate affected mutable views; review events invalidate current review views and local policy assessments. Captured review snapshots and immutable revisions remain fixed. `job.checkpointed` invalidates latest-checkpoint and checkpoint-history query domains, while `job.update_appended` invalidates the job-update query domain: their resource IDs identify appended records rather than the owning job. Refetch only active queries in those domains without expanding each job’s private context. Mark affected inactive pages stale without walking them or fetching their bodies. Multiple events coalesce; no periodic JSON refresh is needed.

The metadata watch has a separate lifecycle from the existing inbox watch, so selecting a worker neither closes it nor changes its identity. Reuse the existing SSE parser, scoped request budgets, abort handling and reconnect/backoff primitives where they are independent of message vocabulary. A reconnect may replay events; expired replay obtains a fresh snapshot and invalidates affected views before resuming. Transient failures show a stale/disconnected status rather than implying current settings. If the metadata watch closes, an explicit Reconnect project updates button starts a new attempt from a fresh presentation snapshot and refreshes affected stored queries before subscribing at its watermark. The attempt owns finite reads and stream cancellation; a project route must be ready before it starts, and changing the inbox worker does not restart it. Terminal authorization/identity failures clear the connection.

Apply theme/headings/branding only from the active verified project session. Masthead, document title and root CSS sit outside the workspace remount and must explicitly reset on disconnect, project switch, route mismatch, canceled connection and terminal authentication failure. Ignore delayed callbacks from the prior session. Store no appearance or credential payload in browser storage. Tabs remain independent. The document title uses the active project name and FireController; disconnected pages use FireController. Render all text literally. The small Powered by FireController link stays linked to the public repository.

## Agent use and proof

The input file contains the complete configuration; the CLI supplies the revision wrapper. File shape, Unicode, keys, colors and bounds are checked before credentials or network calls. The default command budget remains five seconds; replacement returns a completed compact receipt, not a pending operation.

Settings reads are explicit; ordinary context, inbox, job and map reads do not append theme data. The bounded `presentation_read` MCP tool exposes the same explicit snapshot; privileged administrator mutations do not gain an MCP shortcut. Keep source configuration, key and binding for uncertain-write recovery.
