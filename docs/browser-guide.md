# Embedded Browser Guide

## Implemented boundary

`fcd` serves an authenticated workspace with default read-only sessions and a separately published [public project website](public-site.md) from the same origin as its API. It displays project identity, paginated workers and basic jobs, explicit full job briefs and checkpoint details, worker inboxes and explicit conversation pages, plus the [native review workspace](review-workspace.md) for stored queue, PR/run history, findings and fix proof. Incoming messages update through the persistent [message stream](message-events.md). Reads never mark messages seen or acknowledged, edit jobs or contact GitHub. The existing development dashboard remains separate until replacement and migration proof are complete.

Anonymous `/public/{slug}` routes load only approved content, without a private browser connection; projects are private by default. The [browser design](browser.md) owns the broader target. The [project map](project-map.md) adds compact workstream/return-point lists, explicit current and historical editorial snapshots, and deliberately loaded recorded job references. [Project presentation and live metadata](project-presentation.md) add explicit project settings and a separate scoped feed for settings/map/reference updates, with packaged proof at that owner. Explicit browser messaging and administrator appearance controls use the separate opt-in session authority; incoming-message events keep their independent worker scope. Latest checkpoint display and explicit archives passed the focused API tests and actual packaged browser checks described below. Empty presentation overrides preserve the default fire palette and dense responsive layout; configured themes use the validated semantic palette. A small repository attribution remains in the footer.

## Connect and navigate

Run `fcd`, open its printed loopback address and enter a project ID and a credential with read access to that project. Obtain these through the existing [project setup API](local-api.md#project-and-worker-setup); this slice does not add an onboarding wizard. Each connection verifies the service instance and selected project before loading project data.

The credential is used in memory to verify the instance and project and establish a read-only browser session. The browser then discards the credential and clears the password field. The service supplies an encrypted HttpOnly cookie with a 24-hour absolute lifetime; the raw API credential is absent from that cookie, URLs, browser storage and query-cache keys. The unchecked connection option keeps every credential read-only. Explicitly enabling message and appearance changes grants only the [selected browser actions](browser.md#explicit-browser-actions), within the original credential and current grants.

Per-tab `sessionStorage` retains only the versioned instance/project binding, random session selector, expiry and selected worker ID. It contains no API credential, messages or job content. Reload revalidates the saved binding, preserves the current project detail route and restores the selected worker after reading the current worker list. Independent tab selectors prevent connections to different projects from replacing each other's cookies. An ordinary reload or component teardown closes requests without logging out. New connections keep up to eight sessions for this instance within its cookie-size budget, expiring the oldest retained sessions when necessary; an evicted tab asks to connect again. This bounds cookies left by closed tabs.

Disconnect, expired or revoked access, an instance mismatch, or leaving the connected project clears the saved binding and cached data and attempts to expire that session's cookie. A transient network failure preserves the binding for an explicit reconnect. The original credential and project grants are checked on reads and live-stream authorization; revocation therefore terminates access before the cookie's expiry. Reconnect with a credential after expiry or terminal authorization failure. The [browser session API](local-api.md#browser-sessions) owns the transport and cookie contract.

Routes are `/projects/{project_id}`, `/projects/{project_id}/jobs/{job_id}`, `/projects/{project_id}/workers`, `/projects/{project_id}/inbox` and `/projects/{project_id}/inbox/{conversation_id}`, `/projects/{project_id}/reviews`, `/projects/{project_id}/reviews/pulls/{number}`, `/projects/{project_id}/reviews/runs/{run_id}`, `/projects/{project_id}/map`, `/projects/{project_id}/map/entries/{entry_id}` and `/projects/{project_id}/map/entries/{entry_id}/history/{revision}`. Review drill-down links retain an optional `snapshot` query for historical consistency. Choose a worker to follow its incoming inbox. Worker changes cancel the prior view's requests and subscription and clear its cache; they do not alter credentials, assignments or server state. Project-scoped read access permits conversation reads within that project, as documented by the API.

Job detail reads the latest [checkpoint](job-checkpoints.md), including its captured revision, attribution, done/next/blocker and evidence. No-checkpoint state is explicit. The current brief and latest envelope are separate reads: a revision mismatch prompts refresh rather than implying an atomic combined snapshot. Checkpoint history loads only after opening it and remains cursor-paged; closing it stops that active view. Evidence is escaped plain text rather than an executable or automatically opened link.

Native run details include an explicit **Assess captured comparison** panel for the current local review requirements. Opening it reads the [captured-comparison assessment](review-controls.md#captured-comparison-assessment); closing cancels its request, and reopening reads again. Imported history has no assessment control. The panel shows the returned captured target and observation time separately from policy evaluation; it does not verify current GitHub source, CI or merge readiness. Closed panels and ordinary queue reads perform no assessment request.

Job details also show the current read-only ordered [checklist](job-progress.md), with explicit controls for narrative updates and checklist history. Archives load one page only when opened; closing cancels that view and removes it from refresh, and reopening reads current stored data. Brief/checklist revision differences prompt a refresh without hiding the standing brief. Progress text and evidence remain escaped plain text.

“Refresh visible data” rereads only active stored-data queries. There is no timer-based JSON polling, focus-triggered refresh or provider refresh. The project feed invalidates affected jobs, workers, notes, map/reference and current stored review views. It cancels pre-event reads before refetching active views, marks inactive views stale without opening them and coalesces overlapping changes within a page. Captured historical review snapshots and immutable individual revisions remain fixed. Incoming messages retain their separate worker-scoped feed; each indicator describes its own connection. An expired project replay cursor refreshes current visible project views from a new watermark before replay resumes.

## Live delivery and failures

The browser takes an atomic inbox snapshot and its event cursor, then opens authenticated same-origin fetch SSE. Cursor advancement follows successful application to the view. Committed events invalidate relevant active inbox/conversation reads; transport keepalive comments do not trigger reads or appear as activity.

Ordinary API reads share a five-second budget per operation. Stream connection headers have a five-second budget; an established stream stays open with its own cancellation signal. The parser bounds frames to 1 MiB and validates UTF-8, scope, metadata shape and cursor identity. It rejects malformed events rather than exposing arbitrary response text.

After a transient disconnect, the view shows reconnecting and retries stream attachment at capped delays of one, two, four and ten seconds. The last processed cursor survives those attempts in memory. Expired replay requires a fresh snapshot before resubscribing. Access errors terminate delivery and clear the session. A stream with no traffic for 45 seconds is reattached; routine server keepalives keep a healthy idle connection open. Canceling or disconnecting never acknowledges messages.

Project, worker and connection nonce scope query keys. Old-context results cannot populate a new view. Returned text is escaped by React; the app accepts no raw HTML, external images, inline scripts or unrestricted styles. Embedded responses set a same-origin content security policy. Unknown API paths and unavailable assets remain JSON errors rather than receiving application HTML.

## Build and packaging

The client uses React, TypeScript, React Router’s data router and TanStack Query. Vite builds a client-only application; there is no Node server at runtime. Exact dependency versions and the browser lockfile are committed in `webapp/`.

Install both lockfiles and run the repository checks:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm --prefix webapp ci --ignore-scripts --no-audit --no-fund
make check build
```

Use Node.js 22.22 or newer for development. `make check` type-checks the app and runs focused API/SSE tests alongside Go race/vet and documentation checks. `make build` regenerates `internal/webui/assets` and embeds them in `fcd`. CI rebuilds the assets and rejects tracked differences or new untracked output. Commit the generated index, fingerprinted JavaScript/CSS and bundled third-party licenses with their source changes. Source maps and package manifests are not served. Bundled notices are available at `/third-party-licenses.txt`.

Committed assets allow direct `go build ./cmd/fcd` or `go install` without Node; these commands use the checked-in browser build rather than regenerating it. The development Vite proxy targets `127.0.0.1:8080`; Vite results do not substitute for embedded-service browser proof.

## Explicit changes and uncertain results

At connection, leave **Enable message and appearance changes** unchecked for a read-only view. Enable it deliberately with a write credential to send/reply and use recipient **Mark seen** and **Acknowledge** controls. Reading alone changes neither state. Administrator-enabled sessions also show **Settings** for the full project presentation. Settings edits use the observed revision and preserve another editor's changes through visible conflicts; they never publish private appearance to the approved public website.

Action controls keep the original key, body and selected worker after an uncertain response. Use the offered exact retry rather than submitting another action. Recovery details stay in this tab's memory; message drafts and keys are not stored in browser storage. Route and worker changes inside the project retain unresolved intents. Leaving the project or disconnecting asks before discarding unresolved work, and reload/close uses the browser's unsaved-work warning. Confirming that discard or closing the process loses the local recovery context; it does not cancel or reverse a committed server action. Completed actions do not require this warning. Permission/recipient refusal leaves readable views available.
