# Retained Review History

## Implementation status

Versioned storage is integrated locally: immutable typed payload versions, interval membership and indexed current references replace full snapshot-body copying. Full observations, native publication and adjudication use that storage, and focused review tests pass normally and under race. Migration proof preserves retained API responses, signed continuations and receipt bytes from supported older schemas, including omissions, reordered records and historical unfinalized ownership changes. Schema five adds derived current counters and indexed attempt ordering, with bounded recent-run and per-channel latest-attempt reduction. Canonical backup/restore and actual packaged CLI/MCP/browser checks passed at the storage-four checkpoint; the schema-five packaged checkpoint and complete CI are separate required checks; this is not an installed release or a completed growth boundary.

The [review workspace](review-workspace.md#bounded-archive-implementation) already provides explicit attempt pages and browser run/attempt continuation. Existing publication count limits remain until bounded summary/policy queries, transfer and public history coverage are implemented and proven together. Whole-document imports retain their 256 KiB transport bound and single-producer contract; additive mixed-producer transfer remains unimplemented. Current data stays retained; a capacity hold is not permission to delete history or continue an unrecorded provider action.

## Goal

An ongoing project keeps its completed PRs, review rounds, attempts, decisions and fix evidence without reaching a lifetime review quota imposed by its dashboard. An individual command still reads or writes a bounded amount of data. Ordinary jobs, messages and review reads stay independent of provider calls.

## Historical authority

A stable historical identity includes its project, original producer and source record identity. The transfer publisher is separate provenance. Importing a record whose producer describes a native executor never creates native execution authority or coverage; those claims remain bound to actual local journal operations and captured evidence.

Store immutable versions of changed records and reference those versions from retained workspace snapshots. Payload, snapshot visibility and ordering are separate: changing a position or returning after an omission can reuse the same immutable body. Indexed current references advance atomically with the workspace pointer after preflight reads; old current references remain valid throughout staging. Historical snapshots resolve their own membership intervals. Returned historical pages are bounded, but interval lookup is not claimed to use constant CPU as history grows. Do not copy unchanged finding bodies for every unrelated attempt transition. Preserve resource IDs and exact historical snapshot reads, including signed continuations. An old snapshot cannot join to a mutable latest decision or attempt and silently change its meaning.

Derived current counters and attempt-order indexes advance in the same transaction as current references and the workspace pointer. Native compact summaries reduce indexed current candidates and their touched replacements: three recent runs and one latest attempt per supported channel. Timestamp ordering preserves exact instants, nanoseconds and position ties across time-zone offsets. Exclusive startup backfill uses bounded keyset batches and rolls back schema, metadata and derived data together on failure. Ordinary publication checks its previous compact summary against the selected indexed front before replacing it; full migration and backup validation check every current derived row. The bounded publication guard does not claim to detect damage confined to nonwinning cache rows. Derived data never supplies native capture authority.

Finalized counts, run ownership and known finding identities/text remain protected. Enrichment and reviewed decision/fix corrections create another version. Settled attempts cannot reopen, and an existing identity cannot move between PRs, channels, heads or scopes. Explicit superseded/defunct queue retirement changes visibility without erasing historical evidence; merging a PR keeps it visible as completed work.

## Bounded changes and transfer

Native publication updates only its touched historical records and the necessary snapshot references in the same transaction as its journal changes. It performs no provider or filesystem wait inside that transaction. Replace aggregate lifetime count checks with bounded per-operation admission and finite individual record/detail limits.

Historical transfer uses explicit bounded additive batches with stable producer/source keys. Omitted history is retained. A batch binds its selected destination, current revision and normalized content; exact same-key replay returns the original compact receipt under current authorization. A changed request, identity conflict or concurrent revision refuses atomically. Accepted batches can be visible before a larger collection completes, with explicit partial coverage and continuation. An interrupted collection or apply never claims all selected history was imported. Collection remains separate from approval and application.

## Bounded reads

Queue and recent-run summaries remain compact. Run and attempt archives have explicit snapshot-bound pagination, including browser continuation; a PR detail does not return every lifetime attempt. Latest-attempt facts remain useful without downloading that archive. Public views use an explicit bounded history window and coverage/continuation metadata rather than failing after one hundred rounds or silently claiming a complete history.

Native comparison and policy assessment query the relevant evidence set without an unrelated all-head lifetime ceiling. Preserve detection of pending decisions and fixes on earlier heads; a bounded query cannot turn unexamined history into passing evidence. Current policy and native journal/capture authority remain separate from imported display history.

## Migration and proof

Migrate supported retained snapshots and records without changing IDs, producers, counts, decisions, proof or historical bytes. Update schema ownership, canonical backup columns/keys/foreign keys/triggers and logical reference validation together. Restore must retain every referenced historical version and reject missing or cross-project references. Read-only backup inspection validates the exact canonical physical schema and view definitions, foreign keys, interval overlap and ordering, and completeness of current references. Restored instance/signing rotation still invalidates predecessor access and signed cursors; retained snapshot IDs support fresh authorized continuation after activation.

Prove growth beyond current total and per-PR count boundaries, immutable earlier snapshot/cursor reads, finalized identity protection, exact retry, concurrent revision refusal, rollback and restart. Exercise mixed imported/native producers without granting imported coverage. Include actual bounded CLI/MCP/browser pages and public history continuation. Measure touched-record publication and retained bytes on a multi-PR synthetic history; correctness at a higher arbitrary cap is not this proof. The [delivery plan](delivery.md) records completion and installed validation separately.

## Implemented storage proof

The [migration tests](../internal/reviews/history_migration_test.go) compare retained HTTP responses, signed cursors and receipts across supported older schemas, restart and injected migration failures. A 64-snapshot, 512-run, 2,048-finding fixture preserved 1,179,648 bytes of finding detail; its normal migration took about 51 milliseconds. This fixture is not a maximum-size or fleet guarantee. Startup contention tests distinguish the 30-second migration budget from ordinary two-second writes and preserve earlier cancellation and atomic rollback.

The [native growth test](../internal/reviews/history_native_growth_test.go) performs 60 actual native publications across a mixed imported/native workspace. Existing finding bytes stay at 29,184, existing run bodies stay at three, and unrelated PR bodies stay at two; old detail responses and a signed continuation stay unchanged. The [backup tests](../internal/backup/history_inventory_test.go) preserve retained mixed-producer history through real creation, inspection, inactive restore and fresh activation. Rehashed canonical-schema bundles with foreign-key-valid missing parents or historical parent gaps are refused before destination writes. Predecessor access and cursors remain invalid after restore identity/signing rotation.

Clean runtime `cab8a8ad53d929ce8ff7d41ad7c06751c912a1b5` passed actual CLI/MCP/upgrade/publication/map smoke in 1.086 seconds and private/public/archive Chromium checks in 10.678 seconds. The archive workload retains 123 runs and attempts, colliding external IDs from different producers and an old tail after a newer observation, without draining archives automatically. Focused normal/race checks also cover projection, executor recovery, rollback, finalized counts and receiving-side routes. The first full repository run exposed legacy fixture writes to the new read-only views and a removed login-mode field; those fixtures now target the owning physical versions and automatic session contract. Their affected groups pass normally and under race; final CI remains separate. No installed storage migration, unlimited-history publication, additive transfer or operational cutover is claimed.

## Current-index proof

Focused schema-five normal and race tests cover original-reducer parity for all four channels, nanoseconds and time-zone offsets, corrected winners, colliding external IDs from distinct producers, incomplete-run counters, omission/reappearance and reordering. Event-failure injection after current-reference advancement preserves all prior rows and API bytes. Migration preserves older responses and signed continuations; already-current startup does not repeat backfill. Indexed query-plan checks cover recent-three runs and latest-per-channel selection without a temporary sort.

Actual schema-five backup creation, inspection, inactive restore and mixed native/imported adjudication roundtrips pass. Genuine schema-four backups remain supported. Rehashed canonical, foreign-key-valid bundles with damaged counters, ordering keys, ownership or missing derived rows are rejected before destination writes. Focused checks do not establish completed lifetime-cap removal, maximum migration size, fleet throughput or an installed upgrade.
