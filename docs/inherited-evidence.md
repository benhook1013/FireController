# Inherited Source Evidence

## Status and authority

This inventory records behavior and named test scenarios from the public source snapshot at commit [`28263335caa23ef0706a8dc79add7eec4d0fcc53`](https://github.com/benhook1013/FireMUD/tree/28263335caa23ef0706a8dc79add7eec4d0fcc53). The tests were inspected and counted from source; none were executed for this inventory. They are regression evidence, not passing proof for this rebuild and not authority over the target contracts in [product](product.md), [architecture](architecture.md), [agent/client](agent-client.md), [reviews](reviews.md), [browser](browser.md), and [acceptance](acceptance.md).

The rebuild adopts portable coordination and review safety properties where the target documents require them. It changes origin-specific storage, identity, delivery, UI, and policy boundaries to the standalone service contracts. Numerical review policy and deployment conventions are configuration or migration concerns, not universal behavior.

## Cross-cutting coupling and edge cases

- Legacy jobs, inbox, maps, and review state share a SQLite controller database and backup/restore boundary. Bootstrap is explicit; schema/provenance validation must fail closed rather than silently drop unfamiliar state. The standalone target instead owns versioned migrations and complete restore validation.
- Worker identity in the old CLI is supplied metadata used for notices, not authentication. The new server must authorize project scope independently, and the same display name in two projects must never collide.
- The old web projections are the contract consumed by a separately maintained private status site. The standalone browser uses the shared API; any reusable privacy rules still require new API and browser proof.
- Markdown precheck is a write-path dependency in the old runtime. It preserves submitted text, batches fields, and fails before writes if the checker is unavailable; rendering safety is a separate boundary.
- Review source tests cover recovery and fail-closed cases in addition to policy outcomes: per-PR pagination cursors, repeated cursor rejection, partial identity batches, target movement, same-count finding replacement, and retry after an uncertain provider post.
