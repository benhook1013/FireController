# Native Review Execution

## Implementation status

Native execution is the active delivery boundary. The [stored workspace and bound read tools](review-workspace.md) work independently; development reviews still use a separate executor until the native adapters and recovery paths pass their checks. This document owns the implementation boundary for replacing that executor. The [review contract](reviews.md) owns identity, admission, evidence and policy requirements.

The implementation provides: revisioned configuration and queued-operation receipts, a durable attempt/reservation journal, two supervised work slots, fresh source comparison checks, bounded GitHub reads/posts, immutable Git workspaces, included-only CLI execution and structured capture parsing. A private operator catalog loader and immutable filesystem capture store are also implemented. The packaged daemon accepts an optional private CLI capability catalog and composes the source reader, owned Git workspace, included-only process runner and capture store. Without that catalog it runs coordination and evidence controls without provider workers. Hosted dispatch remains unimplemented. The CLI capture-to-journal path records immutable evidence against the admitted anchor, checks the complete pinned changed-file set and retains incomplete results without completed coverage. Local accepted/rejected finding decisions, guarded fix-proof corrections and source finalization are implemented against that ledger. The [native evidence controls](review-controls.md) expose retained evidence, finding decisions, guarded fix references and source finalization through the API, CLI and MCP. The journal enforces bound project-policy revisions and channel pauses. The concrete CLI driver checks fresh selected source facts, stacked predecessors, actual changed-file ceilings, included allowance and pending native findings before execution. Hosted dispatch/recovery, routing, aggregate policy/required-CI assessment and public checkpoint publication remain. The concrete CLI pipeline has passed packaged proof with controlled provider responses and CLI processes; real CodeRabbit execution and live native review cutover remain pending. A terminal attempt state alone creates no review credit.

Focused race tests cover duplicate requests, concurrent reservations, independent channel/account slots, revocation and configuration changes before dispatch, retained trigger intent, interrupted preparation versus possible execution, malformed results, bounded SQL cancellation, strict provider pagination and captures, and process interruption/output limits. The full repository check/build passed. Separate live checks verified real GitHub response shapes and complete collections, fetched and verified pinned public Git objects, and obtained a real CLI allowance observation from the isolated workspace without starting a review. These establish adapter behavior on Linux/WSL, not completed native review execution, deployment cutover, fleet performance or other-platform runtime support.

## Packaged CLI pipeline proof

Actual packaged service and client processes exercised public project, worker, policy, configuration and request APIs against isolated state. A controlled TLS provider fixture and fixed CLI executable drove real source resolution, Git materialization, allowance checks, capture retention and journal/browser publication. The complete passing fixture took 9.693 seconds. Request and same-key replay returned in 3.741 ms and 1.088 ms; ordinary job/inbox reads during blocked execution took 3.544 ms and 4.097 ms.

Same-head and moved-head requests with pending evidence caused no additional allowance or review subprocess. Finding decision, finalization and fix recording closed the source obligations; exact covered comparisons remained held. Changing source after allowance prevented execution. Killing and restarting the daemon during possible execution recovered the original attempt as uncertain without relaunching, inventing a finish or losing earlier captures. Mobile and desktop browser checks passed without JavaScript errors, overflow or persisted bearer credentials.

The fixture made 19 controlled source GETs, three allowance invocations and two review invocations, including one interrupted process. It made no real external provider calls or paid-credit requests. This proves the concrete pipeline under controlled facts; real CodeRabbit account behavior, hosted dispatch, aggregate required-CI assessment and live cutover remain separate checks.

A missing-projection regression passed three packaged-service groups in 2.822 seconds at clean checkpoint `eb24bd9e120f589286a8ea84d5623f7fd69999e7`. An administrator import removed the selected current PR while its controlled review process was blocked. Completion retained unfinalized evidence, released the reservation and preserved the import and historical snapshots without recreating browser facts. Original-key replay and repeated typed reads performed no provider work or durable writes. The run used eleven CLI commands, 26 local HTTP requests, five controlled provider GETs and one each of allowance and review invocations; source/binary hashes stayed unchanged and owned processes/state were removed. This does not establish live provider behavior, aggregate policy sufficiency, browser rendering or operational cutover.

## Ownership and fast requests

The service owns review admission, provider work, retained artifacts and attempt recovery. An agent supplies its bound project plus an expected PR, channel and candidate head; it never supplies a GitHub credential, executable path or mutable working directory. Ordinary queue, job and inbox reads remain provider-free.

A review request validates local arguments, authorization and configured capability, records a durable request and returns a compact receipt before provider preflight. Provider reads, Git preparation and subprocess execution occur under supervised background workers. A waiting adapter follows that operation through the service; an explicit detached request exposes the same receipt for recovery. A lost tool response does not imply that no request or external action happened.

Queued requests, external attempts and completed review evidence are distinct records. A request can be held before any action. An external attempt records preparation, possible posting or process start, active work, and a proven terminal or uncertain outcome. Its retained transition history identifies the actor, expected head, admitted comparison, configuration revision, provider account and external identifiers. Reusing an idempotency key with the same request returns its original receipt; changing the request conflicts.

Each local attempt mutation records one effective UTC timestamp shared by its operation update and transition. It cannot precede valid retained operation or attempt chronology, including after restart or a backwards wall-clock adjustment. Malformed retained timing is rejected without changing the journal. Effective recording time does not establish physical elapsed duration or adjust provider, capture or source-observation timestamps; their attribution and freshness checks remain separate.

## Operator capabilities and project configuration

Private startup configuration supplies named provider capabilities: the GitHub credential reference, CLI executable and its protected authentication context, and explicit provider-account scheduler identities. These are operator-owned settings. Project administration selects permitted capability IDs and channels, queue mode/order, required channels and allowed source configuration through revision-guarded service records. New requests bind both their execution configuration and current project-policy revisions. Local preparation, admission and the final action guard recheck those bindings, actor access and channel pauses; older unbound requests remain held. Project content and worker requests cannot select arbitrary server files, environment variables or commands.

Each queued operation retains a fingerprint of its selected capability, including the configured provider account, channel set and private authentication context. Changing that binding holds old queued work; it never silently adopts a replacement account or credential. Existing unbound operations from the earlier journal schema are retained and held. Replaying an already successful configuration or request key returns its original receipt after local capability changes, subject to current caller authorization; a new action requires a new explicit request.

The catalog is versioned strict JSON, limited to 64 KiB and 32 named capabilities, read from an explicitly selected private regular file. It accepts operator-owned Git/CLI executables and an allowlisted map of authentication home/configuration directories. An optional GitHub credential-file reference resolves relative to the catalog; the token is required for hosted posting and is never passed to the CLI. There is no shell or environment-expression expansion. Safe metadata and formatted diagnostics omit private paths and credentials. Select it explicitly with `fcd --review-catalog /private/path/catalog.json`. This delivery accepts runnable capabilities with only the `cli` channel; a catalog requesting hosted execution fails startup. The default empty catalog starts no provider worker or review polling loop.

The service obtains source through the verified project repository and creates its own bare object cache and per-attempt immutable workspace under its private data directory. A developer checkout is not the execution workspace. Git commands disable ambient hooks and configuration; source preparation does not execute repository install/build hooks. The CLI receives a minimal explicit environment and only its required authentication context, never the service's GitHub credential or another project's profile. This is a trusted local executor capability, not a hostile multi-customer sandbox.

One service process supervises two global work slots. Startup validates driver bindings and commits interrupted-attempt recovery before accepting HTTP requests; asynchronous worker completion has a single retained result. Shutdown cancels owned work and waits within a finite budget before closing storage. Account and exact-target reservations allow at most one active action per provider account and channel and exclude another action against the same repository, PR and channel. Finite deadlines bound each action. One project can occupy both slots; per-project scheduling fairness is not implemented. Coordination remains usable when provider work is slow or unavailable. Multiple active service replicas and remote executors remain outside this delivery.

## Admission and provider boundaries

Resolve the selected project repository by its stable identity and obtain its current canonical name. Refresh the selected PR and the predecessor/default-base facts required by the configured queue; do not refresh unrelated queue members or recapture completed evidence on every request. Cached observations retain time and completeness. Provider pagination must terminate completely before a collection can support admission.

The expected PR/head are assertions. Admission verifies current lifecycle, repository identity, candidate head, effective parent/base and canonical patch identity, applicable active-provider activity, operator stops, required fresh facts and observed account allowance. It records the exact evidence used. A mismatch or incomplete fact holds the request without falling back to another PR.

Before an external action, atomically reserve `(provider, repository_id, PR, action_class)` and retain the attempt intent. Provider-account scheduling is separate from that target reservation. Conflicts remain opaque across project grants. Recheck the external target at the final action boundary; record the admitted identity even if a later provider result belongs to an older head. No provider call or subprocess wait occupies a database transaction.

Hosted and CLI channels have independent cycles and allowance observations. Exhaustion or activity in one does not hold the other unless a real shared reservation or account resource applies. No adapter purchases credits, seats or overage, or selects paid execution after an included allowance is exhausted. Unknown allowance or an ambiguous action remains an explicit hold/uncertainty.

When native projection is enabled, each journal transition updates its browser attempt in the same transaction. Preparing and held are distinct states; held attempts retain their actual stop time. Interrupted active or posting work becomes uncertain without an invented finish time. A missing current PR observation leaves the transition ledger-only; a trusted fresh observation can establish that first row. Publication preserves current PR facts and imported history, and exact replay creates no new snapshot. If retained attempt capacity is already full, the request is durably held before creating an attempt or reservation. If a later administrator observation replaces the snapshot, omits the live native attempt and fills its capacity, automatic transitions remain ledger-only; they neither copy snapshot rows nor block execution or restart recovery. Existing native rows still update at capacity. Explicit publication retains its atomic capacity refusal. Other projection failures roll back the journal transition as well.

Attempt settlement retries only the same guarded local journal transition within a finite budget. It reconciles an already committed transition before retrying and never repeats provider dispatch. If the outcome cannot be recorded, the supervisor reports a failure, cancels its other work and retains reservations for inspection and recovery.

## Hosted adapter

A hosted attempt records its exact command body and unique intent marker before posting a GitHub comment. Retain the returned comment ID and posting time. On a lost response or restart, search the complete scoped provider history for that intent before deciding whether posting occurred. Never blindly repost an uncertain request.

Observe completion against the admitted PR/head, trigger and configured provider actor identity. Import all review comments and the completed summary, including actionable summary-only and outside-diff findings. Empty status reviews and success checks alone are not completed coverage. Incomplete pagination, attribution or captures remain visible without credit.

## CLI adapter

Native CLI process execution requires a supported Unix host. Each invocation owns a separate process group; cancellation, timeout, output overflow and wrapper exit terminate remaining workers in that group. Unsupported hosts reject the native CLI capability before launching a process. Windows clients can still use a remote controller, and installations without a native CLI capability retain their coordination/browser behavior. Equivalent native Windows process-tree ownership remains unimplemented; cross-builds do not establish that runtime guarantee.

The CLI adapter verifies included allowance, prepares the admitted candidate/comparison objects in the owned workspace and executes one allowlisted argument vector. Before issuing its one-use process permit, the runner also requires an explicit available billing observation with usage billing inactive; missing, active or unknown billing facts hold execution. This conservative check matters because [automatic usage billing](https://docs.coderabbit.ai/management/usage-based-addon) can continue beyond included allowance without a per-review credit flag. The observation does not reserve provider quota or prevent an external actor from changing account settings between observation and dispatch. It retains exact source/comparison and executable identities plus bounded stdout/stderr artifacts. Parsing structured review output distinguishes completed capture from failure, cancellation, rate limiting and partial output; exit zero alone is insufficient. Raw capture retention accepts the full unsigned 32-bit exit-status range on a 64-bit reader, including crash statuses; the derived review outcome cannot turn a nonzero exit into completed coverage.

The driver retains one immutable included-allowance observation before admission, tied to its source anchor, actual changed-file count, original actor, policy/configuration revisions, private capability binding and account. Exact local replay has no extra event or permission. New observations recheck current access, source freshness and project file ceiling. These records describe the observation; the runner still consumes its separate fresh one-use permit before starting the process.

Private captures preserve exact stdout/stderr bytes, process-start status, exit code and the measured capture window in a versioned envelope. The start/finish timestamps are explicit canonical UTC values retained before ledger ingestion; they describe the invocation/capture window even when the process did not start. Exact artifact replay reuses both bytes and timestamps. Invalid, missing or reversed timing and unsupported formats fail closed without replacing retained bytes. Their references carry a checksum and byte count rather than a filesystem path. Publication is immutable: an exact retry reconciles the existing artifact, while different bytes or a corrupt existing artifact fail without replacement. Capture storage bounds stdout to 16 MiB and stderr to 64 KiB. Retention alone establishes neither successful execution nor completed coverage.

Transport keepalives and routine process progress stay out of model-facing output. A dispatched command that loses its supervising process is recovered as interrupted or uncertain from retained state; a replacement process does not silently spend another review. Canceling local execution does not recover allowance or erase its evidence.

Provider source reads retain the full validated UTF-8 title within a separate 4096-byte adapter bound. Browser PR metadata uses a trimmed prefix at a complete UTF-8 character boundary within its 500-byte display budget. That display limit does not reject an otherwise valid source comparison; the adapter bound is a local resource limit, not an asserted GitHub title maximum.

## Evidence and the native workspace

The CLI capture ledger is independent of browser snapshots. Trusted runtime integration binds its checksum, timing, structured findings and scope to the exact stored attempt anchor and capability fingerprint. An exact retry returns the original capture receipt after settlement; different evidence conflicts. A scoped full read rechecks current authorization. Recording a capture neither releases its reservation nor marks the attempt completed, finalizes findings or establishes policy sufficiency. The optional configured CLI driver retains and publishes this evidence; the default unconfigured daemon exposes only stored controls.

Current local adjudication rechecks project access, uses revision guards and idempotent receipts, and appends an audit row and compact event with each change. The daemon updates an already-published native browser run in that same transaction; projection failure rolls back the ledger, audit, events and receipt. Missing initial publication remains ledger-only. Finalization requires a completed attempt, complete capture and all findings decided; it freezes the original source counts, including legitimate zero-finding runs. Later decision or fix-reference corrections retain original captures, counts and audit records. A proof-bearing accepted finding cannot be silently rejected and lose its proof. The [evidence controls](review-controls.md) expose these operations through bound agent clients and document stored administrator policy configuration, whose revision and channel pauses are enforced by the local journal; source-dependent file ceilings remain driver-owned. Browser mutations remain unavailable.

Trusted initial CLI publication builds a native run from the retained capture and its current adjudication. The captured head remains separate from current PR facts. Publication can precede attempt settlement, but cannot finalize the source or grant coverage. It preserves original finding identities, partial-result limitations, effective fix references and finalized source counts. Exact replay is read-only; a source present only in historical snapshots cannot be silently recreated.

A missing current PR projection leaves successfully retained CLI evidence in the authoritative ledger without changing a completed execution to uncertain or keeping its reservation. It does not recreate browser facts or finalize the source. Other publication failures remain recoverable failures; a failed retention never becomes a completed capture.

The local CLI comparison check keeps current-comparison coverage separate from pending evidence. Coverage requires a completed native attempt and complete finalized capture for the exact current repository, PR, candidate, base and effective parent, with every finding decided and accepted findings carrying fix proof. Pending completed native evidence is checked across all heads of the selected PR: missing captures, unfinished decisions/finalization and accepted findings without proof block another spend. A ready capture cannot hide another pending capture. The final local action guard repeats this check in its authorization snapshot. Imported history never becomes native execution credit. Repository renames preserve coverage when stable identity and Git objects still match. The indexed lookup examines at most 100 completed CLI operations for the selected PR before loading evidence; excess history produces an explicit capacity hold instead of an unbounded scan or another provider spend. This predicate does not establish aggregate policy sufficiency, CI success or merge readiness. The concrete driver supplies fresh source observations and repeats local authorization before its one-use process action.

New attempts, run evidence, findings, decisions, effective fix proofs and observation freshness are native durable records. Source finalization freezes source counts and identities. Adjudication/fix corrections append guarded evidence; they preserve earlier values and never replace finding text to reuse an old count. Public checkpoint publication is a separate recoverable external action.

Publish workspace projections from those records while preserving imported run IDs, original source identities and retained snapshots. A new native event cannot relabel imported historical evidence as a newly executed run. Native progress publication must not require exporting the whole queue through the administrator import route or reading the old database. Preserve stable historical drill-down and source-count conflicts.

Each run summary carries its original producer in `source`; snapshot metadata identifies the publisher of that observation. Those values can differ. A publication about one target does not refresh the observation age or establish completeness of unrelated PRs. Retained projection capacity is bounded; reaching it must refuse a publication atomically rather than truncate history. Increasing retained scale and reducing snapshot write amplification require separate measured storage work before claiming large review-history throughput.

The browser keeps separate chronological Hosted/CLI rows. It displays real attempt/progress facts and configured policy outcomes when available; missing policy is explicit. Review completion, aggregate sufficiency and merge readiness remain distinct. Humans perform merges. Existing worker, job and message paths remain independent of this domain.

## Cutover proof

Before replacing development review execution, exercise both actual adapters with isolated state and controlled failures, then use the native tool on this project's real queue. Required proof includes duplicate requests and concurrent reservation, exact target and parent movement, partial provider pages, independent quota/cooldown, lost post response/restart recovery, CLI interruption, incomplete captures, summary-only findings, immutable counts and correction history, and unchanged ordinary coordination behavior.

Measure request/receipt latency separately from provider duration and record provider-call scope. Browser and agent reads must continue to work without provider availability. Verify the real history, current native attempt, finding/fix workflow and restart before retiring the separate executor. Its retained private artifacts remain available for inspection; removal is a later explicit maintenance action.
