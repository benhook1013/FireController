# Packaged binary smoke

The separate `make legacyimport migration-smoke` builds the optional migration utility and runs two independent cases against the already built `fc`/`fcd`. `TestPackagedCoordinationImportSmoke` converts and imports explicitly selected current jobs/checkpoints. `TestPackagedOperationalAdoptionSmoke` exercises carried review settings plus selected historical messages through actual utility/CLI/API boundaries. The cases cover compact preview/application, private source provenance, lost-output recovery, later native edits or acknowledgement, restart, and source/input/binary conservation without provider calls or historical message replay. They use explicit private paths and do not override home-directory variables. CI runs this dedicated target on Linux. These synthetic checks do not establish installed migration, Windows/macOS source conversion, canonical live-history acquisition or operational cutover.

Run `make check build` followed by `make smoke`. The smoke target executes the existing `bin/fc`, `bin/fcd` and `bin/fcmcp`; it never builds or changes those binaries. CI runs it after the ordinary checks and build. Missing binaries fail explicitly. The `packaged_smoke` build tag excludes this process-level check from ordinary `go test ./...`; formatting still includes the file.

Each case runs in its own Go test process with a 45-second context and five-second command/readiness/shutdown bounds inside that process’s 60-second timeout. The canonical target and native CI run the coordination and upgrade cases separately, so an earlier case cannot consume a later case’s cleanup budget. The coordination case verifies actual daemon bootstrap/health and private credentials, actual CLI profile creation/doctor/job mutation/exact replay/read, official Go MCP SDK initialization/discovery/read, cancellation of an established quiet stream with concurrent reads and same-session reuse, and daemon restart retaining identity/state/receipts. It checks only the tools needed by the workload, rather than duplicating the tool catalog or a fixed discovery count.

A stopped fixture is provisioned using four authenticated handler calls and one synthetic repository resolver. This trusted setup is separate from the actual executable proof; it does not claim real GitHub repository verification. No SQL manufactures domain state or receipts. Fixture profiles, credentials and databases are private disposable test data. Child environments contain no installed credentials or provider catalog. Unexpected HTTP uses a local denial proxy; there is no provider, Git or review workload. The check does not claim a hostile-network sandbox.

Child stdout must be JSON/protocol data; diagnostics never echo captured private output. Owned processes and local HTTP servers are joined during cleanup, including failures. Logs report input binary hashes and elapsed time. The same bounded workload runs in the Linux job and native Windows/macOS CI. The complete `validate` aggregate passed at `41f3afb412f2e20d35ef1566c81ba9b7b9a9d5f6`, including Linux full checks/build, the executable/browser gates, cross-builds and both native coordination jobs. The expanded retained-data case below has separate newer native proof. This is not browser, container, remote-host, release provenance or throughput proof.

An explicit absolute input directory can validate another already-built set without overwriting the repository outputs:

```sh
FC_SMOKE_BIN_DIR=/absolute/private/bin make smoke
```

Such a run proves only those supplied inputs. Build/source provenance remains the caller's responsibility.

## Native platform gate

The Linux job retains its full checks, cross-compilation and separate Chromium smoke. Native Windows and macOS jobs build all three CGO-free binaries with `-trimpath`, report `go env GOOS GOARCH GOEXE`, then run the same tagged packaged workload against those outputs. They require no Node or browser installation. The single required `validate` job succeeds only when Linux and the entire native matrix succeed; native proof is not inferred from cross-compilation or runner labels. `make workflow-check` runs pinned actionlint before the ordinary `make check` workload, checking workflow structure, expression contexts and action contracts without optional external shell/Python analyzers. The first native workflow attempt was rejected before any jobs ran because a runner path was placed at job scope; its corrected definition uses that context only at step scope.

The daemon uses interrupt-driven clean shutdown on Linux/macOS. Go cannot deliver that interrupt to another Windows process, so Windows deliberately terminates only its owned daemon, requires the expected termination result and joins it within the same bounds. Its subsequent retained identity/state/receipt checks establish crash/restart recovery, not graceful Windows shutdown. MCP still closes stdin through the official SDK and must exit successfully with empty stderr on every platform. Timeout cleanup kills and joins owned processes without converting a failed shutdown into success.

Fixture HOME, USERPROFILE, TMPDIR, TEMP and TMP point to disposable private paths. POSIX permission assertions remain active on Linux/macOS; Windows mode-bit exemptions do not establish ACL isolation. The workload does not prove native provider/review subprocess execution, every CPU architecture, signing/notarization or installation. Actual Windows execution passed both a local native run and the GitHub runner. The first macOS run failed before readiness with a backup-path validation refusal. A local symlinked temporary-root experiment reproduced the same diagnostic fingerprint; resolving only the newly allocated fixture root made both packaged and browser smoke pass against unchanged supplied binaries. The corrected macOS arm64 runner then passed in 0.331 seconds, with a maximum observed CLI invocation of 16 ms, 26 application HTTP requests, one stream, zero external requests and zero surviving owned processes. Windows also passed again at that same `41f3afb` checkpoint. These small runner samples are observations, not latency guarantees. Product path guards and all deadlines remain unchanged. The Linux alias experiment supplied reproduction evidence; the subsequent native runner supplied the macOS execution proof.

## Retained-data startup regression

`make smoke` and the native matrix also run `TestPackagedUpgradeSmoke`. Genuine authenticated API calls create a job, later brief edit, history, checkpoint, message and original receipts. With the private fixture stopped, the case removes only four empty add-only tables and selects the supported jobs4 schema; all other components remain current. A canonical backup and inspection preserve the source and bundle bytes. An identity-preserving copy of that verified database is then opened by the supplied packaged `fcd`.

The check requires jobs4 → jobs6, exactly the four new empty tables, unchanged base/other metadata, and unchanged counts and row hashes for all retained tables, including identities, credentials, original receipt bytes, events and SQLite sequence state. Public reads and original-key replay after the later edit must match exactly, with no added history/events. A second daemon startup must preserve the upgraded state. Cleanup joins each owned daemon; logs contain hashes, counters and timing rather than private output.

The first actual Linux run against unchanged `265af4a` daemon inputs passed in 0.634 seconds with ten HTTP requests, zero external requests and no surviving processes. This is reconstructed historical-schema composition proof. Both native Windows and macOS arm64 jobs then passed the expanded two-case workload at `5cb82482e82673488c66045dce07519010aafd1e`; the macOS upgrade case took 0.359 seconds. The Linux full suite and required aggregate also passed at that checkpoint; Linux, Windows, macOS and the aggregate passed again at `765dca2be6824b564efb12881c1d33988bba55f0`. This does not prove a genuine predecessor binary, retained capture artifacts, constrained container mounts or disaster restore. Windows shutdown remains the explicitly described crash/restart boundary.

## Embedded browser lifecycle

On Linux, `make browser-smoke` runs a separate bounded Chromium case against the existing `fcd`, using the same daemon/bootstrap/authenticated seed helpers. It does not build the daemon or install a browser. Install the Chromium revision selected by the existing pinned Playwright dependency and its Linux system dependencies first:

```sh
cd webapp
npx --no-install playwright install --with-deps chromium
cd ..
make browser-smoke
```

CI installs Chromium and its system dependencies explicitly, then runs this target after the packaged binary smoke. Missing inputs fail rather than silently skipping coverage. The 45-second workload and five-second steps sit inside a 60-second Go-test bound. The lifecycle case checks connection, live coordination and review updates, layout bounds, renewal and reload continuity, and explicit disconnect cleanup. Read-only phases refuse domain writes; a separate authorized phase performs seven browser writes: seen, acknowledge, send, reply, appearance save, an uncertain send, and its exact retry with the original idempotency key after the response is lost. Trusted fixture writes are counted separately from browser actions. The test uses private disposable credentials, bounded output and owned-process cleanup; it never prints raw browser or daemon output.

`FC_SMOKE_BIN_DIR` selects an absolute already-built input directory as above. An optional absolute `FC_BROWSER_EXECUTABLE` selects an explicitly supplied Chromium executable and is reported as an override; it does not prove the pinned default revision. The ordinary target uses Playwright's installed default. This small regression gate complements the broader executed browser matrices and human GUI review; it does not establish two-project isolation, pixel fidelity, full accessibility, physical-phone behavior, installed hosting or fleet performance. The native binary gate above and retained-data container-upgrade validation remain separate from this Linux browser case.

The canonical browser target also runs the diagnostic allowlist guards before launching its browser cases. The lifecycle driver records a bounded private progress snapshot in its disposable fixture, without browser protocol calls. On the global deadline, the Go harness reports only allowlisted phase, checkpoint, operation and counter fields plus the age of the last observed change; it never prints the raw record. Failure-snapshot and cleanup waits remain distinguishable from workload waits. This improves timeout evidence without extending deadlines or identifying a failure cause by itself. Login capability checks combine the real successful POST and rendered project heading with a fresh same-cookie current-session read that verifies exact identity, permissions and persisted expiry. They do not depend on Chromium retaining a response-body handle or completing an unbounded protocol-observer wait.

Use `FC_BROWSER_PROOF_DIR=/absolute/private/path` to retain a masked screenshot and allowlisted numerical diagnostics if uncertain-message recovery fails. The default check keeps no browser artifacts. Diagnostics exclude credentials, raw errors and message bodies.

An actual clipping experiment verified the bounds assertion: the original horizontal-only check passed an injected `max-height`/hidden-overflow heading, while the corrected check rejected the same clipped content and passed the unmodified page. Bounds respect actual clipping ancestors, without treating ordinary visible glyph extents as clipping. An intentional failure also verifies that fixture context cancellation follows daemon cleanup, preserving the useful assertion diagnostic instead of adding a forced-shutdown error. These controlled checks do not establish general visual correctness.

At clean combined checkpoint `8958e68cae8f5195fdf1a8e004a13569dedf7f97`, full `make check build` passed, including 222 browser tests, all Go race tests and vet, workflow/document checks, embedded assets and all three binaries. The canonical packaged and Chromium targets then passed on their first runs against those exact unchanged inputs. Coordination/restart, jobs4-to-jobs6 retained-data upgrade and the narrow browser lifecycle/bounds checks passed, with zero external requests or surviving owned processes. All 584 tracked files and supplied binary hashes stayed unchanged. This is local executable proof; native-platform CI and installed-host behavior remain separately attributable.

## Public project browser

`make browser-smoke` also runs `TestPackagedPublicBrowserSmoke` against the already built daemon. It uses a disposable project, explicitly approved publication and private sentinel records. The separate fixture writer prepares stored review summaries; anonymous Chromium pages use only the public API. The workload checks desktop and 390px rendering, credentials omitted despite an existing cookie, separate Hosted/CLI groups and retained merged work, no-reload summary delivery, frozen history, private-edit silence and unpublication. Page requests to private APIs or external origins fail the workload. The test preserves executable hashes and cleans up its owned service and browser processes.

Use `FC_PUBLIC_BROWSER_PROOF_DIR=/absolute/private/path` to retain desktop, phone and historical screenshots for visual inspection. This runs no live review provider, does not install or rebuild the executable/browser and does not establish physical-phone, remote reverse-proxy, throughput or operational-cutover proof. The [public website contract](../../docs/public-site.md#proof-status) records the executed source checkpoint and remaining validation.

The public browser workload also uses an ordinary bounded observation of 100 new Hosted rounds after three were already published. It checks the preserved public union becoming a 100-round window, an honest outside-view flag, retained CLI history, the window's revision-browser link and unchanged frozen revision one. Another private job edit must leave limited-view bytes, freshness, cursor and page request counts unchanged. The fixture uses twelve explicit writer calls, including those two additional writes, while anonymous pages still perform zero private requests or mutations. This does not establish admission of more than 100 current private rounds; source-query overflow has separate trusted-archive proof.

## Additive prepared review transfer

`make smoke` includes `TestPackagedTransferSmoke`, using an actual administrator profile and the supplied `fc`/`fcd`. Three bounded prepared batches retain 202 runs and attempts on one PR, with overlapping external IDs from two original producers. The workload checks compact SELECT-only partial previews, known and unknown historical times, old snapshot bytes and cursors, and exact recovery of a committed apply whose stdout was lost before later advancement and restart. It preserves native authority and unrelated table values, blocks external traffic and joins owned processes under the existing deadlines. This proves additive prepared transfer, not collection, removal of complete-observation/native limits or live-provider coverage.

## Selected history acquisition

`make smoke` includes `TestPackagedHistoryCollectionSmoke` against the supplied `fc` and `fcd`. A stopped trusted setup selects one synthetic repository; the real daemon then uses its production GitHub HTTPS origin through a loopback-only CONNECT proxy and disposable CA. The fixture permits only credentialed GETs for the selected merged PR and its bounded review/comment pages, denying other destinations and methods. No provider origin override, production test flag, Git executable or installed credential is used.

The workload checks compact receipts and useful default-wait results, a controlled rate-limit pause, ordinary job/message writes while a provider page is blocked, provider-free original-key replay, pinned capture pages, explicit private export with original identities/times/replies and no overwrite, then actual restart and explicit page-one resumption preserving old captures. Unrelated retained tables and supplied binary hashes must remain unchanged apart from deliberate coordination writes. This is controlled-provider acquisition proof, separate from destination import, real GitHub availability, native review credit and installed hosting. The pinned Go 1.27 toolchain honors the child process’s `SSL_CERT_FILE` override on Linux, macOS and Windows without changing machine trust. Native runs must establish their own execution proof; POSIX export-mode checks do not claim Windows ACL isolation. The existing 45-second case, five-second step and 60-second process bounds apply.

## Channel-front review selection

`TestPackagedRunSelectionSmoke`, included in `make smoke`, exercises the actual built daemon, CLI and stdio MCP adapter. A private synthetic operator catalog and a restricted loopback HTTPS/proxy fixture provide source facts. One explicit start selects the expected front and links one normal native operation, deliberately held at a trusted Git stub before review execution. Expected-PR refusal, different wait preferences, original-key replay, lost stdout, configuration changes and restart preserve that link without new source acquisition. Inputs and unrelated data are conserved; owned processes and tunnels are joined.

This Linux fixture uses POSIX stubs and explicit child CA trust and skips other platforms. It performs no real provider calls, allowance spend or captured-review credit. Ordinary cross-platform packaged smoke remains a separate check.
